# Batch 119–129 — Spooky2 User's Guide

Scope: pages 119–129. Target reader: a tool recommending among 48,463 frequency
presets. Gaps specifically hunted: ORGAN / SYSTEM / per-condition protocol
vocabulary; additional Reverse Lookup interpretation guidance; program/preset types
beyond Sweep, Wobble, Feathering, Modulate, Pulse, Harmonic/Holland; ordering &
sequencing; safety text; un-explained UI labels.

> **HEADLINE NEGATIVE FINDING — read this first.**
> **No organ, body-system or per-condition protocol material appears anywhere in
> pages 119–129.** The earlier 73–108 batch's missing-vocabulary flag (brain, gut,
> lung, heart, thyroid) is **NOT** satisfied by this range. Pages 119–129 are a
> continuous run of *Control-tab reference material* — the Generator Control
> Panel, GeneratorX Pro offline storage, and biofeedback-scanning setup and
> interpretation. They cross-reference organ protocols only twice, both already
> known: `Terrain (R) -BY` as a preset chain (p126) and the `RX Herxheimer - DB`
> detox trigger (implied by p123's Hold rationale, p127). **The vocabulary gap
> remains open.** Do not let a batch like this one be read as evidence that the
> range was checked and is clean of protocol content in general — only that this
> particular stretch is a UI reference chapter.

## p124

**The frequency-count grammar — settles how to read the six status numbers (p124).**

| Field | Definition (p124, verbatim) |
|---|---|
| **17 `Dwell`** | "times (in seconds) **progress** of each frequency. If you click `Pause`, this becomes **editable** — useful if you need to jump to a different part of the sweep." |
| **18 `Total (Dwell)`** | "the total number of seconds the frequency will transmit for — **normally 180 seconds, but longer for sweeps**." |
| **19 `Step`** | "the **position number** of the current frequency… if Spooky² is transmitting the 12th frequency in the sequence, this field will display 12." |
| **20 `Total (Steps)`** | "the number of frequencies contained in the **program or sequence**." |
| **21 `Preset`** | "the current preset number in the *chained preset*. **If the current preset is not in a chain, this number will be 1**." |
| **22 `Total (Presets)`** | "when you load a **Chained Preset**, these fields tell you which preset is currently transmitting, and the total number of presets contained in the chain." |

> **`Dwell` is a countdown, editable only while Paused.** `Total : 180` is the
> *nominal* per-frequency dose, with *"longer for sweeps"* as a per-program
> override. `Preset = 1` is the sentinel for "not in a chain" — a cheap
> machine-checkable signal that a preset is standalone.

**`Age Factor [x]` (item 23) — DEFINED, and it is NOT about age (p124).** Verbatim:
*"this **accelerates all running programs for quick tests**. Large values will
force a long preset or Chained Preset to run rapidly through all its frequencies,
**allowing easy checks for errors**."*

> **CORRECTION to a plausible misreading:** `Age Factor` is a **speed multiplier for
> testing**, not a patient-age dose scaler. `[x]` marks it as a multiplier. This is
> the mechanism behind the "test scan / quick check" workflows on p125 and p129.

**`Frequency Adjustment Slider` (item 24) — a live, non-destructive pitch offset
(p124).** *"allows you to adjust the frequency that's currently running, up or
down… Click the `Reset to Default Button` to move the slider back to its default
position."* Item 25: `+/- [x] Hz` sets the step size (1 Hz on p120/p122). This is
the Scoon-Effect-style 1 Hz offset knob (KNOWLEDGE §9d, p147) as a per-run control.

**`Program Column` (item 26) — DEFINED (p124).** *"this lists **all programs in
this sequence**."* The hierarchy is now unambiguous:

```
Chain (Chained Preset)  ->  Preset  ->  Program  ->  Frequency  (dwell sec each)
```

> Most useful structural correction in the batch. **preset** = recommendation unit
> (corpus is organised by preset file); **program** = the unit Reverse Lookup
> reports; **frequency** = the unit dwell applies to. Do not flatten these three.

**`Include Harmonics` / `Include Sub-Harmonics` — actual definitions (p124, items
27–28), NOT in KNOWLEDGE.md.** Verbatim, both: *"when doing a reverse lookup,
include harmonics **(as specified in the `Harmonic Type` pulldown menu just
below)** of the database frequencies for more matches."*

1. These checkboxes **only affect Reverse Lookup** — search-widening options, not a
   treatment parameter. Unrelated to the F2 modulation menu on p119.
2. **`Harmonic Type` governs both**, and is the dropdown captioned `Octave` in the
   GUI. That is why hits get annotated `Salmonella (Octave #3)`.
3. **Harmonics/sub-harmonics are expanded on the DATABASE frequencies being
   matched, not on the query frequencies.** INFERENCE: this is what produces the
   "one frequency maps to many unrelated programs" behaviour of p62.
   **A hit list generated with `Include Harmonics` ticked is inherently noisier
   than one without — the tool should always state which setting produced it.**

## p125

**`Harmonic Type` — DEFINED, and it is a FAMILY (p125, item 29).** Verbatim: *"the
type of harmonics to be used when doing a reverse lookup (**Octave, Decade, etc**)."*

> **NEW:** `Harmonic Type` options include **Octave** and **Decade**. KNOWLEDGE §9.1
> documents only the `Octave` dropdown and the `Octave #N` annotation. **A decade
> expansion (×10) at the same tolerance yields enormously wider matches than an
> octave expansion (×2). Match-set cardinality is therefore a function of Harmonic
> Type, not just tolerance — record `Harmonic Type = Octave|Decade` alongside every
> Reverse Lookup result reported.**

**`% Tolerance` — DEFINED, and the direction of comparison matters (p125, item
30).** Verbatim: *"is the amount of tolerance of error of **your frequency** from
the database frequencies **or harmonics of the database frequencies**."*

> (a) the query frequency is the datum, database entries are the reference;
> (b) the comparison set **expands to the database frequencies' harmonics**, which
> is why tolerance interacts with `Harmonic Type`; (c) the field showing `.25` is
> therefore plausibly **0.25 %** as easily as 25 %. **KNOWLEDGE §12 item 2 gets
> worse, not better: three candidate numbers (25 %, 0.25 %, 0.0125 %) all appear in
> the record. Do not assert any of them; state the field literally as `.25`.**

**`Include [x] Hz in Search` — DEFINED (p125, item 31).** Verbatim: *"you can add a
frequency to be included in the Reverse Lookup. This is useful if you have a
frequency with which you want to do a reverse lookup, **even if the Generator Pane
is currently empty**."*

> **CONFIRMS the p120 INFERENCE and adds the decisive use case: Reverse Lookup does
> not require a running generator or a biofeedback scan.** A single known frequency
> — from a published Rife table, an author PDF — can be looked up directly. This is
> the legitimate, non-diagnostic path for the recommendation tool: *given a target
> frequency, what does the database say is near it?*

**`Go` (item 32).** *"perform the Reverse Lookup operation."*

**`Generator Output` (item 33) — DEFINED.** *"this is where you can **monitor exactly
what Spooky² is sending to each Out** of the generator. Shown for both are
Frequency, Waveform, Duty Cycle, Amplitude, Offset, Phase, Angle, and Current."*
Confirms the p120 table is the complete row set and that `Angle`/`Current` are

**`Save Status` (item 34) — NEW FILE PATH.** Verbatim: *"appends the current

### THE DEFINITIVE GX OFFLINE CAPABILITY BOUNDARY (p126)

> **"The settings saved in offline GeneratorX Pro programs are Frequency,

Exact seven-item allow-list. Anything outside it is *not representable* in a GX
offline program — notably **Phase, Harmonic Type/F2, Modulate, Wobble, Feathering,
Pulse, Spectrum, Chain, Sweep, Frequency Multiplier, Age Factor, Step, Reverse.**
Machine-checkable test the corpus can be run against: a `GX Offline` preset
carrying more than these seven parameter families is malformed.

> **AND the three exclusions (p126), verbatim:**

> *"The following three kinds of common programs and settings **can't be loaded
> into offline GeneratorX Pro programs**: **preset chains** (like the *Terrain (R)
> -BY*), **frequency sweep presets** and **repeat frequency settings**."*

**Consequences, all directly useful:**

1. **Sweep presets and GX Offline are mutually exclusive.** A preset that is a sweep
   cannot be a `GX Offline` program. This is the first place in the guide where a
   sweep is excluded from a delivery path on **structural** rather than therapeutic
   grounds.
2. **Terrain is named a second time** (with p102) as the canonical example of a
   **preset chain** — reinforcing KNOWLEDGE §8's chain ordering as the guide's
   flagship multi-program construct.
3. **"Repeat frequency settings" cannot cross into GX offline.** Combined with
   KNOWLEDGE §3.2 (`Repeat Each Frequency / Program / Sequence / Chain`), a preset's
   *repeat* structure is **lost** in a GX offline conversion. Any run-time duration
   computed from a GX offline program must ignore repeat counts.
4. Combined with item 34 on p125 (`Status.csv` carries Frequency, Waveform,
   Amplitude, Offset, Phase, Angle, Current), the GX offline store is a **strict
   subset** of what the Control tab can hold. INFERENCE: a GX offline program is
   best modelled as a flat (frequency, waveform, amplitude, offset, duty, gate,
   dwell) table with no nesting — i.e. **one program, never a sequence.**

> *Remote (slowest, 7 days) → Contact (7 days) → Plasma (fastest, 4 days)*, i.e.

**Tool rules that follow directly (p127):**

1. **A hit list is ordered by RESPONSE MAGNITUDE, not by disease severity.** The

   strongly — which includes the >50 % of harmless and beneficial flora.
2. **A single scan is explicitly incomplete.** The guide says so twice ("Repeated
