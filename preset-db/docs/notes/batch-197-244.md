That is the whole of it. There is **no** description of how a reverse lookup is invoked, no menu path, no description of what it returns, and no screenshot of it in these 48 pages. What can be *inferred* (label this as inference, not a document statement):

- It is an operation performed on the loaded database and is slower than loading Spooky itself, so it operates over the whole database (~185,000 entries across five databases, per the feature list in an earlier batch).
- Timings scale with disk speed, not RAM (see p243–244 Summary). This makes it almost certainly a **full scan / index query over the frequency database**, i.e. the user types a frequency or a name and gets back matching database entries — i.e. the mechanism behind "which disease does this frequency belong to" and, in reverse, "what frequencies are listed for this pathogen".
- **Recommendation for the tool:** do not promise the user a "Reverse Lookup button". The evidence supports only "Reverse Lookup is a real, named, slow operation in Spooky2 that is faster on SSD than on a spinning hard drive, and it is typically the slowest thing the software does." Anything more specific must come from another source.
